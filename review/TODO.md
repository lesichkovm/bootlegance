# Bootlegance — Remaining Work

Tracks what is left after the Bootstrap 6 batch port (all 87 v5 themes now have a
`themes/v6/{slug}/` counterpart generated by script) and the v5 preview
standardization. Ordered roughly by priority.

---

## 1. Regenerate v6 screenshots

The 85 auto-ported themes ship **v5 screenshots as placeholders**
(`screenshot.png` / `screenshot-light.png`). They show the right palette but
the wrong component set (Bootstrap 5 markup, wrong carousel/badges/cards).

- Flatly and Yeti have real v6 captures — do not overwrite those.
- The repo's `generate_screenshots.py` can't launch Chromium on this machine
  (missing `libnspr4.so`); run it on a machine with Playwright deps, or capture
  via a browser driver.
- Serve the repo over HTTP for capture (`file:` is blocked by browser MCP):
  `python -m http.server 8765` → `http://127.0.0.1:8765/themes/v6/{slug}/index.html`

## 2. Manual component-override ports per theme

Auto-ported `theme.css` files are header-marked:

> Auto-ported from the v5 token declarations; component-level overrides
> from the v5 theme.css may still need manual porting.

Token mapping (palette, surfaces, radii, links, fonts) is done. What remains
is each theme's *signature chrome* — per-theme judgment, no batch script:

- **Custom/mechanical themes** (highest effort): `adwaita`, `win98`,
  `terminal`, `mac-classic`, `carbon`, `fluent`, `material-3`, `cyberpunk`,
  `glassmorphism`, `neo-brutalism`, `high-contrast`, `pantheon`, `whitehall`,
  `kde-breeze`, `ant-design` — distinctive component styling (borders, shadows,
  textures) that needs hand porting to v6 selectors (`.menu`, `.dialog`,
  `.drawer`, `.check`/`.radio`/`.switch`, `<details>` accordion).
- **Bootswatch ports**: hover-state button shades, colored navbar menus,
  pagination details, badge tweaks — mostly cosmetic; verify visually.
- **Luminance guesses to verify**: contrast text was auto-chosen by palette
  luminance; scan themes with light primaries (`minty`, `simplex`, `lumen`,
  `journal`, `united` if present) for wrong contrast picks.

## 3. Verification pass

- Scroll-verify every `themes/v6/{slug}/index.html` top-to-bottom (the preview
  covers ~40 component groups; silent removed-class failures render blank, not
  broken — same class of bug as the `bg-dark` carousel issue).
- Check **dark mode** on every theme — `light-dark()` pairs were auto-picked
  from v5 dark blocks; some themes had asymmetric dark palettes.
- Check **component-override correctness** on flatly/yeti still stands after
  any future batch regen (the generator script must exclude
  `themes/v6/flatly` and `themes/v6/yeti` or restore from git).
- Console is clean apart from known alpha quirks (combobox double-init, favicon
  404 on local server).

## 4. Keep the generator script

The batch porter was run inline (not saved). If a full re-port is ever needed
(e.g. alpha.2 changes tokens), save it to `scripts/port_v5_to_v6.py` with a
`--skip flatly yeti` flag before rerunning.

## 5. Alpha version tracking

- All v6 files pin `bootstrap@6.0.0-alpha.1` (CSS + `bootstrap.bundle.min.js`
  module). When upstream releases alpha.2/beta, bump together everywhere and
  re-verify — the alpha already broke the skill's documented markup once
  (`.bg-dark`/`.bg-light` removal, combobox double-init).
- Re-check `.agents/reference/bootstrap-v6-llms-full.txt` against the new
  release and re-fetch if stale.

## 7. v5 collection (lower priority leftovers)

- **Per-theme bespoke sections** — some themes (adwaita header bars, win98
